## v0.7.0 更新：安全和可靠性

### 安全

- **安装脚本可以先校验再运行**：`get.sh` 随 Release 发布并附 `SHA256SUMS`。推荐的安装命令改成一行里「下载 → 核对 SHA256 → 才运行」，对不上就停下：
  ```
  cd /tmp && curl -fsSLO https://github.com/lyr05142002-dot/Q7Y/releases/latest/download/get.sh && echo "<下面列的 get.sh 校验值>  get.sh" | sha256sum -c - && sh get.sh
  ```
  README 里有写好校验值、可以直接复制的版本。原来的 `curl | sh` 保留为「快速方式」
- **`litebox update` 也先校验**：核对不上就停止，什么都不改
- **分流规则校验后再更新**：以前规则由内核自己每天下载，实测下载到出错网页或空文件时会照样覆盖，规则直接变成 0 条。现在由 `litebox rules-update` 每天凌晨下载并检查（空文件、网页、格式、比上一版少一半以上），不通过就继续用旧版；通过了才替换，并且只让内核重读这一个规则集，不重启、不断开连接。结果在 `litebox doctor` 和 `/etc/litebox/rules-update.log` 里能看到
- **视频作者的个人条目移出默认规则**：他的网站、他用的机场域名、VPS 和宽带 IP 等放进单独的文件，默认不启用（`litebox personal on` 可启用）

### 可靠性

- **修复访客网络断网**：开着访客网络（或 Docker 等）时，这些网络在装 LiteBox 后会整个上不了网。现在会自动放行，和主网络按同样的规则分流（不想让访客用机场流量的设置方法见 README）
- **降级模式醒目提示**：缺 ipset / ip-full 或者是 fw4 时，安装结尾和 `litebox status` 会写明「当前为降级模式」、原因和补装命令
- **看门狗间隔可以改**：`litebox watchdog-interval 分钟数`（1–30，默认 5）
- 规则文件缺失时看门狗每小时在后台补下载

### 文档

- README 分开写真机数据、x86 云端数据和还没实机验证的部分；补充 IPv6、访客网络、设备加密 DNS 的检查和关闭方法，以及内核重启后的影响；新增 [CHANGELOG](https://github.com/lyr05142002-dot/Q7Y/blob/main/CHANGELOG.md)

**从旧版升级**：执行 `litebox update`。旧配置会自动改成「校验后更新规则」（改之前备份为 `config.yaml.pre-0.7`），作者个人条目也会被分出去。想用 `litebox personal on` 开关，需要 `litebox update --reset-config`（订阅、面板密码保留）。从 v0.7.0 起，之后的 `litebox update` 都会先校验安装脚本。

## 下载哪个

| 文件 | 说明 |
|---|---|
| **litebox-arm64-offline.zip** | **推荐离线安装用**。已带 mihomo 内核和面板，路由器连不上 GitHub 也能装。适用于 aarch64 路由器（GL-MT3600BE 等） |
| get.sh | 一键安装的入口脚本，按 README 先核对校验值再运行 |
| litebox.zip | 只有脚本，安装时联网下载内核和面板，支持 aarch64 / armv7 / x86_64 |
| litebox.tar.gz | 给 `get.sh` 用，一般不用手动下载 |
| mihomo-v1.19.31-source.tar.gz | mihomo v1.19.31 源码（GPL-3.0 要求随二进制提供），安装用不到 |
| SHA256SUMS | 上面所有文件的 SHA256 |

每个文件也各附一个 `.sha256` 校验文件。完整的图文教程见 [README](https://github.com/lyr05142002-dot/Q7Y#图文安装教程)。

## 包含的组件

- mihomo **v1.19.31**（GPL-3.0）
- zashboard **v3.29.1**（MIT，无字体版）
- 内核和面板都锁定版本，安装时校验 SHA256
